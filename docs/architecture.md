# HW1 架构与接口约定

状态：接口设计，尚未实现。本文约定代码如何拆分与交接；实际函数名或路径若改变，应先同步更新本文和调用方。

## 代码布局

```text
pyproject.toml          # 0 号：安装 src/hw1 包并声明依赖
src/hw1/
  data.py             # 1 号：解析数据、校验列约定、提供固定划分
  experiment.py       # 0 号：通过 fit/predict 训练并统一计算指标
  reporting.py        # 0 号：保存结构化结果与生成两类图
experiments/
  data/run.py          # 1 号：数据统计、检查和预处理分析
  linear/run.py        # 2 号：线性或正则化模型及优化
  tree/run.py          # 3 号：树或集成模型及优化
  robustness/run.py    # 4 号：样本量与输入噪声分析
  final/run.py         # 0 号：冻结参数后的最终测试与汇总
tests/                 # 0、1 号分别维护各自公共接口的行为测试
docs/analysis/         # 每位同学各自的实验方法、结果与解释
docs/figures/          # 报告采用的精选图片
outputs/               # 本地生成的中间结果，不提交
```

0 号负责仓库维护，1 号负责数据统计与预处理；这两个角色由同一位同学承担。公共模块只接收数据和符合 scikit-learn `fit/predict` 约定的模型。项目通过根目录的 `pyproject.toml` 安装 `src/hw1`，实验脚本只调用下表约定的公开函数。实验脚本负责选择算法、设置参数和解释结果。每个实验脚本可独立从命令行运行；无需扫描目录、自动注册模型或共享可变状态。模型选型和调参逻辑留在对应实验目录，公共模块只实现一次数据协议与评价规则。

## 公共接口

下表是要实现的接口，不是当前已有代码。`RegressionDataset` 持有 `X`（`n × 39` 的有限实数）和 `y`（长度 `n` 的 `k-inf`）；`EvaluationSplit` 持有训练与评价两组数据、阶段标识和评价行标识；`ExperimentResult` 持有实验名称、目标、阶段、评价行标识、参数说明、MAE、RMSE、R²、真实值和预测值。结构可以用数据类表达，不必为每个字段再建包装模块。

| 维护角色 | 模块接口 | 调用者得到什么 | 不变量与错误方式 |
| --- | --- | --- | --- |
| 1 号 | `load_dataset(path) -> RegressionDataset` | 读取任意给定路径的原始数据，交回 39 个输入与 `k-inf` 目标 | 按空白分隔、无表头、恰好 41 列；第 2 列 `PPPF` 不进入 `X`；缺列、非数值或非有限值应报出带路径的明确错误。列顺序是项目假设，不是 UCI 明示元数据 |
| 1 号 | `make_validation_split(data, *, seed=42, validation_fraction=0.2) -> EvaluationSplit` | 从 `raw.csv` 得到可复现的训练/验证数据 | 相同输入和种子得到相同划分；两部分不重叠；所有模型使用同一划分 |
| 1 号 | `make_final_split(raw, holdout) -> EvaluationSplit` | 将完整 `raw.csv` 作为训练、`test.csv` 作为最终评价数据 | 只由最终整合脚本在模型与参数确定后调用；校验输入维度和两份数据无完全相同的行，不从 `test.csv` 学习预处理参数 |
| 0 号 | `evaluate_model(name, estimator, split, *, metadata=None) -> ExperimentResult` | 拟合模型、预测并计算统一指标，返回可检查的结果 | 模型须支持 `fit/predict`；每次评价使用独立的未训练模型实例或克隆，预处理随 Pipeline 在训练部分拟合；预测长度不符或出现非有限值时报错；函数本身不写文件 |
| 0 号 | `save_run(result, output_dir)` | 写出指标与参数摘要、逐样本真实值/预测值、真实值与预测值对比图 | 输出目录由调用者指定；文件固定为 `metrics.json`、`predictions.csv`、`prediction_vs_true.png`；只保存 `ExperimentResult`，不重新训练或计算指标 |
| 0 号 | `save_comparison(results, output_dir)` | 根据多个结果生成 `comparison.png` 模型性能对比图 | 只比较相同评价阶段、同一目标及同一批评价行的结果；条件不一致时明确报错 |

此接口把解析、划分、评价和写出封装在少数公共入口后面。模型与拓展实验的负责人无需知道原始 CSV 的列位置或重写指标与画图逻辑；公共模块的行为测试也只通过这些入口观察结果。

## 实验文件约定

2、3 号各自在 `run.py` 中提供一个简单的 `build_model(variant)` 函数，`variant` 至少接受 `baseline` 和 `optimized`，返回**未训练**且支持 `fit/predict` 的模型或 Pipeline。这个函数供本人的命令行实验和 4 号鲁棒性实验复用；没有中央模型注册表。优化准则由模型负责人选择并在分析文档中说明，所有候选只接触 `raw.csv` 的训练/验证数据。如果使用交叉验证调参，预处理步骤应放进 Pipeline，在每个训练折内重新拟合。

`metrics.json` 记录实验名称、阶段、目标、评价行标识、数据划分种子、参数设置、调参依据和三项指标；`predictions.csv` 按评价行标识记录真实值与预测值。评价行标识用于核对不同模型是否真的在同一批样本上比较，不依赖输出文件的排序或目录名称。

1 号在 `experiments/data/run.py` 中统计数据规模、分布、缺失与异常情况，并把处理选择及结果写入 `docs/analysis/data.md`。公共数据模块负责解析、检查和划分；模型特有的标准化等变换随各自的 Pipeline 在训练数据上拟合。

各模型实验脚本调用公共接口运行并保存结果。2、3 号分别负责自己的真实值与预测值图、优化前后比较和方法解释。4 号复用两种 `optimized` 模型：样本量实验只改变固定训练集的子集大小，验证集保持不变；输入噪声实验只扰动验证输入的副本，训练数据和目标值保持不变。每个条件用独立输出目录，记录样本量或噪声强度及随机种子；拓展趋势图由 4 号绘制。0 号在参数冻结后运行 `experiments/final/run.py`，对完整 `raw.csv` 重新拟合选定模型，再在 `test.csv` 上统一评估并生成最终性能比较图。
