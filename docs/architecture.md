# Linear_regression 架构与接口约定

状态：数据、模型与鲁棒性入口已实现；0 号的通用训练评价和报告接口仍待完成。本文约定代码如何拆分与交接；实际函数名或路径若改变，应同步更新本文和调用方。

## 代码布局

```text
pyproject.toml            # 0 号待完成：安装包并声明依赖
src/
  linear_regression/
    data.py              # 1 号：解析数据、校验列约定、提供固定划分
    experiment.py        # 0 号：已提供通用三指标计算；训练评价接口待完成
    reporting.py         # 0 号待完成：保存结构化结果与生成比较图
    experiments/
      data/run.py        # 1 号：数据统计、检查和预处理分析
      linear/run.py      # 2 号：线性或正则化模型及优化
      tree/run.py        # 3 号：固定随机森林模型
      robustness/run.py  # 4 号：样本量与输入噪声分析
      final/run.py       # 0 号：冻结参数后的最终测试与汇总
  tests/                 # 0、1 号分别维护各自公共接口的行为测试
docs/analysis/         # 每位同学各自的实验方法、结果与解释
outputs/               # 实验生成的指标、逐样本预测与图
```

0 号负责仓库维护，4 号负责鲁棒性拓展；这两个角色由同一位同学承担。1 号独立负责数据统计与预处理。所有 Python 源码和测试放在 `src/`。公共模块只接收数据和符合 scikit-learn `fit/predict` 约定的模型。目前根目录尚无 `pyproject.toml`，运行时从仓库根目录设置 `PYTHONPATH=src`。每个实验脚本可独立从命令行运行；无需扫描目录、自动注册模型或共享可变状态。模型选型和调参逻辑留在对应实验目录。

## 公共接口

下表同时列出现有和待完成的接口。`RegressionDataset` 持有 `X`（`n × 39` 的有限实数）和 `y`（长度 `n` 的 `k-inf`）；`EvaluationSplit` 持有训练与评价两组数据、阶段标识和评价行标识。计划中的 `ExperimentResult` 应包含实验名称、目标、阶段、评价行标识、参数说明、三项指标、真实值和预测值。

| 维护角色 | 模块接口 | 状态与用途 | 不变量与错误方式 |
| --- | --- | --- | --- |
| 1 号 | `load_dataset(path) -> RegressionDataset` | 读取任意给定路径的原始数据，交回 39 个输入与 `k-inf` 目标 | 按空白分隔、无表头、恰好 41 列；第 2 列 `PPPF` 不进入 `X`；缺列、非数值或非有限值应报出带路径的明确错误。列顺序是项目假设，不是 UCI 明示元数据 |
| 1 号 | `make_validation_split(data, *, seed=42, validation_fraction=0.2) -> EvaluationSplit` | 从 `raw.csv` 得到可复现的训练/验证数据 | 相同输入和种子得到相同划分；两部分不重叠；所有模型使用同一划分 |
| 1 号 | `make_final_split(raw, holdout) -> EvaluationSplit` | 将完整 `raw.csv` 作为训练、`test.csv` 作为最终评价数据 | 只由最终整合脚本在模型与参数确定后调用；校验输入维度和两份数据无完全相同的行，不从 `test.csv` 学习预处理参数 |
| 0 号 | `regression_metrics(y_true, y_pred) -> dict` | 已实现；统一返回 MAE、RMSE、R² | 必须是一维、等长、至少两项的有限数值；否则报错 |
| 0 号 | `evaluate_model(name, estimator, split, *, metadata=None) -> ExperimentResult` | 待完成；拟合模型、预测并计算统一指标 | 模型须支持 `fit/predict`；每次评价使用独立的未训练模型实例或克隆；函数本身不写文件 |
| 0 号 | `save_run(result, output_dir)` | 待完成；写出指标、逐样本预测与预测图 | 输出目录由调用者指定，生成文件统一位于 `outputs/` |
| 0 号 | `save_comparison(results, output_dir)` | 待完成；生成模型性能比较图 | 只比较相同评价阶段、目标及评价行的结果；条件不一致时报错 |

数据解析、划分和三指标计算已有公共入口。现阶段线性与树实验仍各自保存结果；0 号后续应统一训练评价与报告写出，再让两条路线接入。

## 实验文件约定

2 号在 `linear/run.py` 中提供 `build_model(variant)`，支持 `baseline` 和 `optimized`；3 号在 `tree/model.py` 中提供 `build_model('optimized')`，只需固定随机森林方案。两者返回**未训练**且支持 `fit/predict` 的 Pipeline，供本人的命令行实验和 4 号复用；没有中央模型注册表。作业要求的优化前后对比由线性路线承担。所有候选只接触 `raw.csv` 的训练/验证数据；若使用交叉验证调参，预处理步骤应在每个训练折内重新拟合。

`metrics.json` 记录实验名称、阶段、目标、评价行标识、数据划分种子、参数设置、调参依据和三项指标；`predictions.csv` 按评价行标识记录真实值与预测值。评价行标识用于核对不同模型是否真的在同一批样本上比较，不依赖输出文件的排序或目录名称。

1 号在 `src/linear_regression/experiments/data/run.py` 中统计数据规模、分布、缺失与异常情况，并把处理选择及结果写入 `docs/analysis/data.md`。公共数据模块负责解析、检查和划分；模型特有的标准化等变换随各自的 Pipeline 在训练数据上拟合。

2、3 号分别负责自己的真实值与预测值图和方法解释；2 号另负责优化前后比较。4 号复用两种 `optimized` 模型：样本量取固定训练集的 10%、50%、100%，前两档各用三个种子抽取嵌套子集，验证集保持不变；100% 只训练一次，保持原始训练行顺序。噪声实验用完整训练集模型，只扰动验证输入副本，标准差取训练集逐特征标准差的 0%、1%、5%、10%，后三档各用三个噪声种子，两模型共用同一扰动。噪声不裁剪，记录超出 0.7–5.0 的输入比例。每个条件在 `outputs/robustness/` 下有独立目录，记录训练及评价行、三项指标和预测值；汇总 CSV、协议 JSON 和趋势图也放在该目录。0 号在参数冻结后运行最终测试入口，对完整 `raw.csv` 重新拟合选定模型，再在 `test.csv` 上统一评估。

## 验证与维护

0、1 号分别维护自己负责的公共接口测试。测试使用小型合成数据及简单的 `fit/predict` 替身，验证列解析、目标列排除、划分可复现、评价指标、文件输出和错误方式；不把替身当成作业模型。测试应从上述接口调用，不依赖内部辅助函数。框架完成时需提供一条本地测试命令和一条可运行的命令行示例。

四人直接提交到 `main`，目前没有 PR 或自动检查。每次修改公共模块时同步检查两种模型和鲁棒性脚本的调用是否仍满足接口；提交前手动运行相关测试，把验证命令和结果写进对应 GitHub Issue。原始数据保持不变；实验生成的指标、预测和图统一放在 `outputs/`，文字分析放在 `docs/analysis/`。
